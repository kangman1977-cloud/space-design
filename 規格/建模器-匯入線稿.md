## 匯入線稿（2026-08-22 完成，`0b86cb8`）

Illustrator 畫好的線稿存成 SVG 丟進來，封閉輪廓擠出成 3D 物件，內孔自動挖掉。
`js/sketch/svgPath.js`（解析與攤平）＋ `js/sketch/profile.js`（輪廓與單位）
＋ `js/build/extrude.js`（三角化與擠出）＋ `js/ui/importPanel.js`（介面）。
工具列「匯入線稿」。

### 為什麼是這一項，不是內建繪圖工具

kang 說核心是編輯，並提到貝茲線、匯入圖片描圖、匯入 AI 線稿三件事。
**那三件其實是同一個 2D 草圖環境的三個入口**，差別只在輪廓從哪來。

先做「別人給的」而不是「自己畫的」，理由是：**他天天在用 Illustrator，
而瀏覽器裡做的貝茲工具永遠不會比 Illustrator 好用** ——
手感、快捷鍵、平滑控制點、路徑管理員，那是人家做了三十年的東西。
在最順手的工具裡畫完丟進來，再用建模器真正獨有的東西
（剖面分切、展開、STL）把它做出來，這樣分工才對。

工程量也是反過來的：匯入一天做完，內建繪圖是從零長一個工具。

### 為什麼選 SVG，不選 DXF

| | |
|---|---|
| **DXF 會把曲線毀掉** | Illustrator 匯出 DXF 時貝茲被拆成直線段，**拆多細控制不了**。之後展開或剖面分切只能照那個精度做 |
| **SVG 保留控制點** | 離散化由我們自己決定，要多精確就多精確 |
| **一次只開一條路** | 兩種格式一起做 ＝ 兩倍的地方會靜靜出錯。DXF 進來是散線段，串成封閉輪廓那段剖面分切已經寫好了（`section.js` 的 `chain()`），第二輪直接接得上 |

### Illustrator 的匯出設定（實測過）

`檔案 → 另存新檔 → SVG`，選項這樣調：

| 選項 | 設定 | 為什麼 |
|---|---|---|
| **回應式** | ❗**一定要取消勾選** | 勾了會**把 `width`／`height` 拿掉**只留 viewBox，尺寸就無從判斷，每次都得手動校正 |
| 樣式設定 | **簡報屬性**（＝呈現屬性） | 「內部 CSS」會把樣式丟進 `<style>` 用 class 引用，得再寫一個 CSS 解析器 |
| 物件 ID | **圖層名稱** | 路徑帶著圖層名，報錯時講得出「圖層『外框』那條沒封閉」 |
| 影像 | 連結 | 不讀圖，嵌入只會讓檔案暴肥 |
| 小數 | 2 就夠 | 最糟情況也是 0.01mm，遠小於雷切的切口寬度 |
| 縮小 | 不勾 | 出問題時打得開來看 |

**圖上有文字要切的話，先在 Illustrator 裡「建立外框」再匯出。**
文字在 SVG 裡有好幾種存法，轉成外框之後就只是一般路徑。
**一個形狀放一個圖層並命名**，錯誤訊息才講得出名字。

### 尺寸：三層防護，而且確認的是「大小」不是「單位」

尺寸是這條路上最容易靜靜出錯的東西：算錯的話**圖一模一樣、
東西做出來全錯**，而且要切完料才發現。

確認視窗**不問「這是什麼單位」**。單位是抽象的，看到「mm」還得在腦子裡
換算一次才知道對不對；**外框尺寸是立刻知道的**——「我那個明明 40 公分寬，
怎麼變成 4 公分」，一眼就抓得到。所以視窗最上面是換算後的實際外框，用大字。

| 層 | 做法 |
|---|---|
| 一 | 讀檔案自己宣告的（`width`／`height` 對 `viewBox`）—— **這不是猜，是讀** |
| 二 | 讀不到就明講「這個檔沒寫尺寸，下面的大小是猜的」，**不偷偷給預設值** |
| 三 | 還是不對 → 直接輸入「這張圖的整體寬度其實是幾公分」反算比例 |

比例來源會顯示在卡片上，猜的時候數字變黃色。

### 擠出件是參數體，不是死網格

存的是**輪廓 ＋ 高度**（`{type:'extrude', h, shapes:[…]}`），
所以匯入之後還能在右側面板改高度重新生成，也吃得下布林、陣列、
剖面分切、展開、STL。這是「關鍵決定 2：存參數，不存三角形」的延伸。

輪廓存成扁平陣列 `[x,y,x,y,…]` 而不是 `{x,y}` 物件 ——
描一張圖動輒幾千點，扁平陣列檔案小一半以上。實測那個測試檔 7.2 KB。

**`extrude` 刻意不放進 `PRIM_DEFAULTS`。** 那是「新增」下拉選單的來源，
而擠出件沒有輪廓就生不出來，放進去等於在選單裡擺一個按了會壞的項目。
放在 `BUILDERS` 裡就夠了 —— `buildSrc()` 認得它，存讀檔／布林／陣列
因此自動支援。

### 一個形狀一個物件（預設）／合成一個（可選）

匯入視窗有一個勾選框，**預設是一個形狀一個物件**（kang 2026-08-22 選的）。

| | 適合 |
|---|---|
| **一個形狀一個物件**（預設） | 招牌字這種每個字要單獨調位置的。**版面完全維持原樣**，只是變成幾個各自有原點的物件，並用**圖層名**命名（他的檔會變成「匯入線稿測試－A」「－B」）|
| 合成一個 | 一個 logo 內部好幾塊、不希望相對位置被動到的 |

合著的隨時可以在右側面板按「**打散**」拆開，版面一樣不會跑。

> ⚠ **這裡原本寫著「要拆的人可以用現成的打散」—— 那句是錯的。**
> 打散當時只對陣列有效，匯入件按不到那顆按鈕。
> 我在日誌裡承諾了一個不存在的退路，而且是靠那個退路才決定
> 「預設合成一個」的。經過見坑第 34 條。

### 原點放在形狀自己的中心

**置中做在幾何上**（匯入時把輪廓點減掉中心），`obj.pos` 留在原點。

第一版是反過來的：網格留在 SVG 的畫布座標上，把**物件**搬到 `pos = -中心`
去抵銷。畫面上看起來一樣，但物件的原點在很遠的地方 ——
gizmo 長在原點上，**旋轉與縮放也都繞著那個遠處的點在轉**。
kang 一看畫面就問「控制桿為什麼不在物件上」。經過見坑第 33 條。

### ★ 真轉角：上游知道的事，不要在中途丟掉（`b2e9d24`）

**這是匯入這條路上最值錢的一段，比座標還值錢。**

貝茲曲線的錨點**自己知道**它是平滑點還是轉角 —— 平滑點的進出控制把手
是共線的，轉角才會岔開。攤平成折線之後這個資訊就沒了，
剩下一串一模一樣的頂點，下游只能從角度大小去猜。

實測 kang 的一個 S 字：**真轉角 7 個，攤平後 196 個轉折點**。
展開圖因此標了 196 道折彎、398 個接合編號，整張圖是一團綠色數字。

> **這不是演算法問題，是資訊問題。**
> 對照坑第 10 條：那次是「一段圓弧切一格，資訊真的不存在」，所以只能保守；
> 這次是**資訊一直都在，是我在攤平時丟掉的**。

修法是把它帶下來，不是把猜測寫得更聰明：

```
svgPath.js  每個輸出點帶 corner 旗標（比較進出切線，門檻 3°）
profile.js  旗標跟著座標走
extrude.js  側牆的垂直邊：真轉角標折線，其餘標 smooth
mesh.js     半邊多一個 smooth 欄位（見「關鍵決定」第 6 條）
flatten.js  連續的平滑折線 ＝ 一條曲線帶
```

| | 之前 | 之後 |
|---|---|---|
| S 側面折彎 | 196 道 | **12 處**（曲線帶 4 ＋ 真轉角 8）|
| 接合編號 | 398 個 | **20 段**，每個恰好出現兩次 |
| 面板編號 | 198 個 | **7 段**（涵蓋 1/87/57/10/1/41/1 條邊）|

**3° 這個門檻抄自 kang 自己在用的 `SideUnfold.jsx`**
（`D:\彩藝通ERP系統\轉檔代理程式\SideUnfold.jsx`，Illustrator 指令碼）。
那支程式產出的圖他驗過很多次，沒有理由另外發明一個數字。
判準（比較進出切線）也是照抄它的 `findCorners()`。

> **值得記住的做法**：他先給我截圖說明想法，我提出一個用角度門檻去猜的方案，
> 他接著說「你也可以參考一支程式」。**讀那支程式的十分鐘，
> 換掉了一個註定會在自由曲線上失敗的設計。**
> 跟「動手前先要真實檔案」是同一件事 —— 而這次真實的東西是他的程式。

轉角索引跟座標一起存在參數體裡（`oc` / `hc`）。
**少了它，檔案重開之後展開圖就會從「12 處」變回「196 道」**——
而且座標完全正確，看不出哪裡不對，只覺得圖突然變得讀不懂了。
