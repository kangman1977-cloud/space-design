## 六個關鍵決定（第 3、5 條在 2026-08-22 修訂，第 6 條當天新增）

**1. 資料結構用半邊（half-edge），不用面清單**
展開引擎最常問「這條邊隔壁是哪個面」。面清單每問一次要翻遍全部的面，
半邊是 O(1)。第 6 期的面編輯也非它不可。

**2. 存參數，不存三角形**
方塊存 `{type:'box',w:60,h:45,d:40}`，不是 12 個三角形的座標。
檔案小、看得懂、能回頭改尺寸重新生成。
只有被布林或面編輯改過、回不去參數的物件才存網格（`bake()` 之後）。
這對應 Blender 的 `.blend` 與 `.obj` 的差別，主要走前者。

**3. 物件分「實體 solid」與「板件 sheet」**
　　⚠ **「只有 sheet 能展開」已於 2026-08-22 推翻（`91a7f03`）**

兩者的精確意思：

| | 網格代表什麼 | 板厚的作用 |
|---|---|---|
| **實體 solid** | 封閉外殼，**就是物件的外表面** | 對幾何完全沒有作用 |
| **板件 sheet** | 開放曲面、零厚度，代表**板厚的正中間（中性面）** | 顯示與 STL 加厚時才用到 |

原本規定只有 sheet 能展開，理由是「要展開的東西一定有板厚，
而板厚會改變展開尺寸（折彎時中性層才是不變的）」。**那是鈑金的道理。**

但這套工具是切開再接合、接縫銑 45 度斜接，**板厚由斜面自動吸收**，
每一片就是切到外緣尺寸 —— 而實體的網格本來就是外表面。
直接展開它就是正確答案。

證據：同一個 60×45×40 的方塊，標成實體與標成板件，展開結果**完全一樣**
（1 片、面積 13800 cm²、展開長 145、展開寬 210）。
擋著的時候使用者只能手動改標籤繞過去，而繞過去拿到的是同一組數字 ——
**證明擋的只是標籤，不是幾何。**

連帶：「要不要加厚」的判斷也從 `kind` 這個標籤改成**網格開不開放**
（`mesh.isClosed()`）。理由見坑第 8 條 ——
kind 是使用者隨手可改的標籤，封閉與否才是幾何事實。

**板件現在只剩一種用途**：單純一片平的東西（背板、擋板）。
那種情況中性面跟外皮沒差別，不會出問題。

**4. 布林運算用 Manifold，而且只有 `bool.js` 一個檔案碰得到它**
（2026-08-21 定案，**推翻了原本「換成 BVH 加速版」的規劃**）

原訂要用 `three-bvh-csg`。實測同一題（方塊 60×45×40 挖 ⌀20 貫孔）：

| | three-bvh-csg | Manifold |
|---|---|---|
| 耗時 | 40 ms | 0 ms |
| 三角形 | 376 | 144 |
| 尤拉數（應為 0） | −113 ✗ | 0 ✓ |
| 網格封閉 | 否 | 是 |
| 結構問題 | 244 項 | 0 項 |

兩邊體積都對、畫面也一樣，差在結構：`three-bvh-csg` 把原三角形切開再拼回去，
**切完之後鄰居關係斷了 506 處**。而展開引擎問的第一個問題就是
「這條邊隔壁是哪個面」，斷掉的地方答不出來，第 3 期會直接失效。
那是它的設計取捨，不是等人修就會好的 bug。

Manifold（`elalish/manifold`，Apache-2.0）的設計目標就是保證輸出封閉可接。
**它不是 Google 的產品** —— 作者 Emmett Lalish 寫它時任職 Google（20% 專案），
現已離職至 Wētā FX，程式碼在他個人帳號下。使用者含 OpenSCAD、Blender、
Godot Engine、BRL-CAD、Babylon.js、trimesh。

**風險控管**：它只被 `js/build/bool.js` import，其他程式碼一律透過我們自己的
介面呼叫。要換掉它就改那一個檔，運算樹格式、面板、Undo、存讀檔都不用動。
這是「規則分開、幾何共用」原則套用在外部相依上的版本。

**5. 折彎存「內側圓角 R ＋ K 因子」，不存中性層半徑**
（2026-08-21 第 3 期定案）
　　🔴 **這條已經不影響任何展開尺寸**（2026-08-23，`4361556`）。

　　⚠ 原本寫的是「這條只對『捲得起來的材料』成立」（2026-08-22 補的適用條件）。
　　**那個限定作廢了** —— 現在的規則不看材料：
　　**展開尺寸 ＝ 網格攤平後的總和**（見 `PROJECT_LOG.md`「尺寸的依據」）。

　　整套 K 因子／中性層是**金屬折彎**的模型：材料被拉伸，所以要算中性層。
　　板材不是這樣做的 —— 它是銑 45 度 V 溝再折，**外皮長度不變**，
　　沒有拉伸也就沒有中性層。差別見下一節「板材與金屬的差別」。

　　**K 因子現在只剩兩個用途**，兩個都不是圖面尺寸：
　　① 決定參數體生成時的圓弧半徑（`neutralRadius()`，影響網格本身長什麼樣）
　　② 算展開圖上標的「內側 R」（純標註）
　　⚠ `neutralRadius(0, k, t)` 回傳 **0** 而不是 `k×t` —— 內側 R 填 0
　　　就是**尖角折，一片弧面都不生**。這一點推論不出來，會害人（2026-08-23 踩過）。

　　珍珠板那筆材料的 K 值留 0.5 只是因為欄位要有值。
　　⏳ 待辦排著「K 因子收起來」—— 主力材料用不到，擺在介面上只會讓人以為漏設。

折彎時外側被拉長、內側被壓縮，中間有一層長度不變，叫**中性層**，
下料長度必須照它算。中性層位置由板厚與 K 因子決定：

```
中性層半徑 rn = 內側R + K × 板厚
一道折彎的展開長 BA = θ × rn
```

**為什麼存內側 R 而不是中性層**：中性層是算出來的，現場量不到。
師傅講「折 R3」、圖面標的、模具標的，全部都是內側圓角。

**差多少**（3mm 鐵板、內 R3、折 90 度、四道）：
照內側 R 算 18.8mm，照中性層算 26.4mm，**差 7.6mm**，折完裝不上去。

K 是**材料屬性**（軟鋼 0.40、不鏽鋼 0.45、鋁 0.35、帆布與紙 0.50），
所以預設值放在 `unfold/rules.js` 的材料表，面板可覆寫。
幾何那邊只負責照公式算 —— 又是同一條「規則分開、幾何共用」。

**6. 邊上有兩個標記，回答的是兩個不同的問題**
（2026-08-22 新增，`b2e9d24`）

| 欄位 | 回答什麼 | 誰決定 |
|---|---|---|
| `role`（free / fold / cut） | **製造問題**：這條邊要切、要折、還是不管 | 材料規則、使用者標的分片 |
| `smooth`（true / false） | **形狀問題**：它是造型的一部分，還是曲面被切成小面的產物 | **上游**（貝茲錨點、參數體） |

原本只有 `role`。混在一起的後果是：下游想知道「這一段是不是一條曲線」時
沒有東西可問，只能從角度大小猜 —— 而猜在自由曲線上一定失敗
（一個 S 字的側面猜出 196 道折彎）。

**界線要講清楚，這不是萬靈丹：**

- **布林運算之後會消失。** Manifold 不認得我們的旗標，輸出是全新的網格
- **從 STL 匯進來的從來沒有。** 別人給的檔案裡沒有這個資訊
- **自由拉點之後可能變成謊話。** 標成平滑的邊，拉完可能已經不平滑了
  （跟分片標記在形狀改過之後是同一個問題）

那些情況還是只能回頭用角度猜。**有上游的就準，沒上游的就得猜。**

存檔時跟 `roles` 一樣用**頂點索引配對**存，不用 id ——
id 每次載入都重新編號，存了也對不回來。

## 參數體一覽（九種）

| 類型 | 標籤 | 種類 | 備註 |
|---|---|---|---|
| `box` | 方塊 | 實體 | |
| `cylinder` | 圓柱 | 實體 | `openEnded` 可只留側面（側面才是可展的） |
| `cone` | 錐體 | 實體 | 上下半徑可不同，做錐形接頭 |
| `sphere` | 球 | 實體 | 不可展，展開一定要切分近似 |
| `prism` | 角柱 | 實體 | 分段數少的圓柱。六角、八角在鈑金常見 |
| `tube` | 管 | 實體 | 中空。**χ＝0**（中間通了）。自己接半邊結構，不經三角形 |
| `roundBox` | 圓角方塊 | 實體 | 只倒四條垂直邊。**圓角是可展的圓柱面** |
| `plate` | 平板 | **板件** | 開放的單面，沒有厚度 |
| `bend` | 折板 | **板件** | 折彎序列，見下 |

**板件（sheet）是開放的面，不是實體。** 厚度是 `ModelObject.thickness`，
畫面上的厚度由 `mesh.shell()` 在**顯示時**加上去，文件裡不存。
`isSheetPrim(type)` 決定新增時的 kind。

### 折板的折彎序列

```
{ type:'bend', w, first, arcSeg, k,
  bends: [ {angle, ri, len}, ... ] }    // 轉幾度、內側圓角、轉完再走多長
```

一道＝L 型；兩道同向＝U 型；兩道一正一負＝Z 型。想折幾道就加幾道。
**寫死 L/U 只能做兩種，序列涵蓋全部，而且展開讀的就是它。**

`ri` 是**內側圓角**（師傅與圖面講的那個 R），`k` 是 K 因子。
中性層半徑 `rn = ri + k × 板厚` 由 `neutralRadius()` 算，
展開長由 `bendAllowance()` / `bendDevelopedLength()` 算 ——
**這三個函式是展開長度的唯一權威來源**，見「關鍵決定」第 5 條。

板厚不存在 src 裡（同一份參數換個板厚就是另一件事，不該有兩份
各自為政的板厚），而是由 `buildSrc(src, t)` 從 ModelObject 傳進來。
遞迴時用閉包帶下去，所以 `bool.js` 與 `array.js` 完全不必知道有這回事。

折彎圓弧被切成 `arcSeg` 段，段與段不共面，`autoMarkFolds()` 會自動
標成折線 —— 這是半邊結構的「邊角色」欄位第一次真正派上用場。
**`arcSeg` 下限是 2**，理由見「踩過的坑」第 10 條。

**資料流是單向的**：`操作 → 改 Doc → hist.commit() → view.sync(doc) → 畫面更新`
畫面永遠是「文件的投影」，自己不存狀態。
所以 Undo 只要把文件換回舊快照，畫面自然跟著回去，不必為每個功能寫反向操作。

核心邏輯完全不依賴 three.js 以外的東西，也不碰 DOM，
**因此可以在 Node 環境下直接跑測試**（第 1 期的驗證就是這樣做的）。


## 半邊結構速查

```js
he.v      這條半邊的起點
he.face   所屬的面；null ＝ 邊界半邊
he.next   同一面上的下一條（繞一圈回到自己）
he.twin   反向的那一條；一條「邊」＝ 兩條半邊
he.role   'free' | 'fold'（折線）| 'cut'（切割線）
```

- 走訪不重複的邊用 `mesh.edges()`（只回傳 id 較小的那條半邊）
- **設定邊的角色一定要用 `mesh.setRole()`**，它會同時設兩條半邊。
  只設單邊的話，`edges()` 可能剛好讀到另一條，看起來就像沒設（實際踩過）
- `mesh.dihedral(he)` 回傳轉折角：0 ＝ 共面、正 ＝ 凸（山折）、負 ＝ 凹（谷折）
- 開放網格（板件）的邊界會自動補上 `face === null` 的邊界半邊並串成迴圈，
  且自動標記為 `cut`


## 交換格式規劃（第 8 期用）

主要走**自訂 JSON**（長期穩定的關鍵是格式在自己手上）。

> **修正（2026-08-21）**：原本這裡寫「glTF 當附加的單向出口
> （給外部軟體、3D 列印看）」—— **glTF 不是 3D 列印的格式**，
> 切片軟體吃的是 STL 或 3MF。3D 列印那條路已經由第 3.5 期的
> STL 匯出解決。glTF 若要做，用途是「給別人看 3D 模型」，不是列印。

```
{ type:'model-mesh', v:1, unit:'cm', head:{...},
  models:[ { name, qty, w,h,z, mesh:{pos,idx,col}, src:{...} } ] }
```

**三個約定必須對齊平面規劃器，否則匯入會錯位**：
單位 cm（不是 mm）／原點在物件中心、`z` 從地面起算／建模器 (x,y) → 平面規劃器 2D 的 (x,y)。

**效能是真限制**：iPad 上 r128 同時畫多個模型，面數必須控制。
匯出時要提供精細度選項並顯示面數，超過門檻就警告。
