**主檔案**：`組裝系統結構說明表.html`（獨立網頁，單位 **cm**）

## 用途
取代目前用 Illustrator 手工畫的「組裝系統結構說明表」。輸入需求尺寸 → 自動排料 →
產生展開計算式、正面／側面圖、備料明細，可列印或存 PNG。

## 標準料（公司實際規格，cm）
`26 / 34 / 40 / 46 / 60 / 94 / 150 / 200 / 292 / 300`
- 預設 **292 與 300 只當立柱、不當橫料**（由實際案例回推的慣例），可用勾選調整
- 立柱斷面預設 4cm

## 資料結構（v2：一個案件多張說明表）
```
DOC = {
  head: { date, no, name },        // 全案共用表頭
  sheets: [ sheet, ... ],          // 多張說明表
  cur: 0                           // 目前編輯第幾張
}
sheet = { name, qty, req:{w,h,d}, ps, lv:{f,b,d},
          bays:[{len,pieces}], postH, postHPieces, depth:{len,pieces}, pickSig }
```
- `qty` ＝這張說明表要做**幾套**（同一組配置重複製作）。圖形不變，備料自動乘上去。
  `computeBOM()` 每個品項同時回傳 `per`（單套）與 `qty`（＝per×套數），
  `cut`／`seats`／`bars` 皆已含套數。已驗算：一張 3 套 ＝ 三張各 1 套。
- `S` 是模組層變數，永遠指向 `DOC.sheets[DOC.cur]`
- 左側欄位是「編輯介面」：切換說明表時 `syncToDOM()`，欄位改動時 `syncFromDOM()`
- `withSheet(i, fn)` 可暫時把 `S` 切到第 i 張執行 fn 再切回（批次匯出／合併備料用）
- 標準料勾選與排料條件（容許差、每組、最多座數、單跨接料）是**全案共用**
- 讀檔相容舊版單張格式（`v` 不等於 2 時自動包成一張）

## 核心邏輯
```
系統寬 = 4 + 跨距1 + 4 + 跨距2 + 4 + … （n 支立柱、n-1 個跨距）
系統深 = 4 + 深度跨距 + 4
系統高 = 立柱長
```
- 括號外＝客戶需求尺寸，括號內＝標準料湊出的實際組裝尺寸
- 跨距可由 1～3 支標準料接起來，寫成 `(150+26)`
- 「前3後2」＝正面 3 層橫料、背面 2 層 → **每個跨距 5 支橫料**
- 深度料：每座前後連接，層數可設（預設 2）

## 演算法
- **跨距排列**：分層 DP，`dp[k][w]` ＝ 恰好 k 個跨距、佔用 ≤ w 的最大佔用量；
  另有可達性表 `reach[k][w]` 用來列出每個座數的前 N 名方案
- **自動選用偏好**：差距 ≤ 容許差（預設 30cm）之中，取「**接料最少 → 座數最少 → 差距最小**」
- **立柱／深度選料**：單支優先；單支差距超過容許差才考慮接料

## 驗算結果（對照公司實際兩張表）
| 案例 | 需求寬 | 公司原表 | 程式自動選用 |
|---|---|---|---|
| ABA-0107 | 290 | `4+60+4+200+4=272` | 相同 ✓ |
| ABA-0125 | 400 | `4+200+4+(150+26)+4=388` | `4+34+4+150+4+200+4=400`（差 0、單支料） |

高 220 → 立柱 200 ✓　深 36 → 34 ✓（皆與原表一致）

ABA-0125 程式給的方案客觀上更好（差 0 且不需接料），公司原排法可能有現場或庫存因素。
把「每組顯示」調大即可在 3 座那組看到 388 的排法。**若之後確認有其他排料偏好規則，改
`autoPick()` 的排序條件即可。**

## 功能
- **一個案件多張說明表**：上方分頁列切換，可新增／複製／改名／前後移動／刪除；
  表上右上角標示「名稱（第幾張/總數）」
- **每張可設套數**：分頁標籤顯示 `×3`，表上右上角標「×3 套」，
  備料明細框加註單套用量，右側面板以 `(單套×套數)` 呈現，CSV 有「單套／套數／總數量」三欄
- **備料可切換「這張」與「全案合計」**
- **批次輸出**：列印全部（A4 橫向、一張一頁）、PNG 一次匯出全部、CSV 含分張明細＋全案合計
- **可指定存放位置**：工具列「指定存放位置」勾選後，單檔匯出會跳「另存新檔」；
  「全部 PNG」則先選一次資料夾再整批寫入。用 File System Access API
  （`showSaveFilePicker` / `showDirectoryPicker`），偵測不到或被擋時自動退回一般下載並提示一次。
  相關函式：`saveBlob()` / `downloadBlob()` / `dataURLtoBlob()`（同步轉檔，避免 await 吃掉使用者手勢）
- 表頭欄位（進場日期／客戶單號／案件名稱）為全案共用
- 排料方案依座數分組，每組列出前 N 名，點選即套用
- 逐跨距手動改（下拉選標準料或接料組合）、可增刪跨距
- 說明表 Canvas 輸出（虛線格、正面圖、側面圖、展開式、備料明細框），PNG／列印／PDF
- 備料明細 + 實際切料統計，可匯出 CSV
- 3D 立體預覽（等角／前／側／俯視）
- JSON 存讀檔、localStorage 自動暫存（key: `sys_sheet`）

## 已知細節
- **立柱斷面寬**（`pS`，預設 4）＝展開式裡的「4」，每支立柱佔掉的寬度
- 說明表的紅線用**固定線寬 9px** 繪製，但側視圖比例被放大約 3 倍，
  若橫線畫到外緣（0～總深）會超出立柱線。因此橫線一律畫到**頭尾立柱的中心線**為止，
  端點由接點圓標蓋住。正面圖同樣處理。

## 平板支援（進行中，分支 `touch`）
**設計原則：事件入口分開，動作邏輯共用。** 桌機的 `mouse*` 路徑保持原行為，
觸控是另外新增的入口，兩者最後呼叫同一組動作函式，所以計算結果保證一致，
未來要改邏輯也只改一處。

- 3D 視角：共用 `orbitBegin / orbitMove / orbitEnd / orbitZoom / orbitPanBy`
  - 滑鼠：左鍵轉、右鍵平移、滾輪縮放（與原本完全相同）
  - 觸控：單指轉、雙指捏合縮放＋雙指拖曳平移
- 側欄分隔線：共用 `grabStart / grabMove / grabEnd`，滑鼠與觸控各接一組入口
- 說明表預覽：新增 `SV{z,x,y}` 縮放狀態，雙指捏合以手指中心為基準縮放
  （已驗算按住的點不會位移），單指拖曳平移，右下角有 −／⤢／＋ 按鈕
- CSS 隔離：
  - `@media (pointer:coarse)` 加大點擊目標 → 只對手指生效，滑鼠桌機不受影響
  - `@media (max-width:1100px)` 側欄改抽屜（含遮罩、點擊關閉）→ **1100px 以上完全維持原版面**
  - `touch-action` 只設在 3D 畫布、分隔線、說明表預覽，其餘保留瀏覽器預設
  - `overscroll-behavior:none` 擋掉下拉重新整理搶走拖曳

**iPad 實測（2026-08-20）**：單指旋轉、雙指縮放平移、說明表放大讀字、
抽屜側欄開關、iOS 鍵盤不擋輸入框 — 全部正常。

### 空間平面規劃器的觸控（同一套原則）
- 2D 畫布共用 `canvasBegin / canvasMove / canvasEnd / canvasZoomAt / canvasPanBy`
  - `canvasBegin(sx,sy,opt)` 的 opt：`pan`（強制平移）／`shift`（加選）／`marquee`（強制框選）
  - 滑鼠：中鍵右鍵空白鍵平移、左鍵拖曳、Shift 加選、滾輪縮放（與原本相同）
  - 觸控：**單指在物件／把手上＝移動縮放旋轉；單指在空白處＝平移畫布；
    空白處按住約 0.45 秒＝轉為框選（會跳提示）；雙指＝捏合縮放＋平移**
- 3D 共用 `orb3Begin / orb3Move / orb3Zoom / orb3PanBy`
- **第一人稱漫遊在觸控裝置隱藏**（`#mWalk` 於 `pointer:coarse` 設 display:none），
  因為需要滑鼠鎖定，iPad 不支援
- 把手尺寸依裝置調整：`HS` 桌機 7px／觸控 12px，命中寬容值 `HGRAB` 2px／14px
