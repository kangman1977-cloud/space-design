### 怎麼做到的

- `index.html`：9 組外面包一層 `<div id="toolBox">`（原本的位置、內容一行都沒改）；`#toolBox { display: contents }` ⇒ 在工具列裡時這一層不存在、照舊一起排。
- `main.js` `placeTools()`：面板開著 ⇒ 在面板最上面建「工具」區、把 `#toolBox` 搬進去；面板收起來 ⇒ 搬回工具列。開場（`restoreUI()`）與收合（`setCollapsed()`，先搬再 `updateBar()`）都叫它。
  搬的是同一批元件 ⇒ 按鈕接好的功能、`updateBar()` 管的出現／消失全部跟著走。
- `hideEmptyGroups()`：收空的組 `#bar` 與 `#toolBox` 兩邊都問；工具區一組都沒有 ⇒ 標題一起收。
- 功能地圖（`ai/catalog.js` `whereOf()`）：`#toolBox` 裡的寫「工具：…」（不管現在擺在面板還是工具列）；`ai/catalogInfo.js` 組名一起改、多一個「工具」大組。
- 畫面上講「按工具列的「刪除面」／「補洞」」的三句改成「按右邊「工具」那一區的…」。

### 🔴 坑：「工具」區一定要用 `document.getElementById` 找

`main.js` 的 `$()` 找不到元件時會回一個**沒放進畫面的替身**（檔頭那一則：舊頁面配新程式時不讓整個停住）—— **替身永遠是真的**。
第一版寫 `let sec = $('pTools'); if (!sec) { 建 }` ⇒ 永遠不建、`sec.appendChild(box)` 把 9 組搬進替身 ⇒ **整組從畫面上消失**，主控台只有一則「找不到 snapNum…」。
回歸測試抓不到（版面在測試環境跑不起來），本機版畫面撞到。⇒ 改成 `document.getElementById`，回歸測試守著「`$('pTools')` 一處都不准有」。
⭐ 普遍版：**用 `$()` 問「有沒有」永遠得到「有」** —— 要判斷有沒有，一律 `document.getElementById`。

### 1a 補：按鈕＋數字格＋單位綁成一組（kang 2026-10-27「同意你的建議」）

**病因**：面板只有 300 寬 ⇒ 拉點線面選了面時有 7 處格子掉到下一行、跟它的按鈕分開（數值、影響半徑、選轉角、選相似、隔一個選一個、內縮、切一刀的座標），`cm`、`公分` 也會單獨一行。
以前在工具列上比較寬、少見 —— kang 2026-08-29 看到過「鎖角度」的「度」被拆開，當時定「併進之後的功能介面討論一起處理」，就是這一次。

**做法**（`ui/keepPairs.js`，開場 `placeTools()` 建「工具」區時包一次）：外面多包一層 `span.keep`（不換行），元件本身一個都沒換。

| 收什麼 | 例子 |
|---|---|
| 前面連著的名字；沒有名字 ⇒ 前面那一顆按鈕 | 「內縮」＋寬度、「離面」＋格子 |
| 名字是單位（度、cm…）⇒ 再帶它前面那一顆按鈕 | 「鎖角度」＋「度」＋格子 |
| 緊挨著的格子都算同一組 | 導角寬度＋段數、切一刀方向＋座標 |
| 後面的單位、單位按鈕、後面⛔ 接格子的名字 | 「公分」、「cm」「mm」、「Y：0 ～ 45」、「cm 一段」|
| ⛔ 收：名字後面接格子 ⇒ 是下一組的名字；組名 | 「離左邊」「離下邊」各自一組 |

裡面全部藏起來 ⇒ 這一組也收（`.keep:not(:has(> :not([hidden])))`）；名字的小字樣式 `.grp > .lbl` 加上 `.keep > .lbl`。
名字跟它的格子在同一層 ⇒ AI 幫手「名字旁邊那一格」（`ai/do.js` `fieldOf()`）照舊找得到。

**驗過的（AI，本機埠 8814）**：工具區包了 35 組；拉點線面全選面時 1920／1366／1024 寬 **被拆開 0 處、超出面板 0 處、面板⛔ 左右捲**；
功能地圖的名字跟包之前比，只有「參考線」那一組的下拉從「cm」（以前叫錯）變成「這個方向現有的參考線」，其他一樣（另兩處不同是畫面狀態不同：有沒有選東西）；
回歸測試 4900 → 4902（綁法六種排法、開場包一次＋樣式）；在複本裡改壞 7 處全部抓到（單位名字⛔ 帶按鈕、名字後面接格子也收、組名也收、單位按鈕⛔ 收、開場⛔ 包、全藏時⛔ 收、名字樣式只套直屬），每處都跑到「通過 N」、沒改壞時 4902 全過。

## 1b：「工具」區拉出來變浮動視窗（2026-10-27 做，kang 2026-10-27 驗收 OK）

### 規則

| | |
|---|---|
| **拉出來** | 面板「工具」標題旁的「拉出來 ↗」⇒ 變成浮動視窗 |
| **放回** | 浮動視窗上的「放回面板 ↘」，或面板那一條的「放回面板」⇒ 回面板；面板收著的話一起打開 |
| **一開始在哪** | 3D 畫面左上角（左側直條右邊、工具列下面，各留 12）；拖過之後記住那裡 |
| **大小** | 寬 300（跟面板一樣，綁好的組不重排）；高跟著內容，最多到畫面底下（留 12），超過在視窗裡捲 |
| **收成一條** | 「收起 ▴」⇒ 只留標題列「工具」；「展開 ▾」回來；記住 |
| **拖** | 拉住標題列（按鈕上按下去不算）；滑鼠、手指同一套；放開才記位置 |
| **夾在畫面裡** | 整個寬度放得下就整個放進來；太下面 ⇒ 標題列至少留 40 在畫面裡（拖得回來）；畫面變小時挪回來，記住的位置不改（回到大畫面就回原處） |
| **面板收起來** | 工具自動變浮動視窗（**取代 1a 的「回到上方工具列」**）；面板打開時：自己拉出來的照舊浮著、因為收面板才浮出來的自動回面板 |
| **拉出來時面板上** | 只留一條「工具在浮動視窗」＋「放回面板」（⛔ 整區不見，看起來像壞掉）|
| **記在哪** | 瀏覽器 `modeler.ui.collapse`（跟工具列／面板收合同一個，跟人走）：`toolPop`、`toolPos`、`toolFold` |
| **疊在哪一層** | 第 30 層：工具列（20）上面、展開圖那些視窗（60）下面 |

### 怎麼做到的

- 新 `ui/toolFloat.js`：`makeFloat()` 建視窗＋拖、`clampPos()` 夾在畫面裡（純算、測試直接叫）、`placeFloat()` 擺位置、`fitHeight()` 算高度。
- `main.js` `placeTools()`：`float = 面板收著 || toolPop` ⇒ `#toolBox` 搬進浮動視窗或面板「工具」區；`setToolPop()` 拉出來／放回；`refloat` 在 resize 事件與 `#app` 大小變了（`ResizeObserver`）時挪回畫面裡。
- `hideEmptyGroups()`：浮動視窗「該浮而且裡面有東西」才出現 —— 🔴 照 id 問、⛔ 讀 `toolFloat` 變數（那一支開場很早就被叫，變數還沒宣告 ⇒ 讀它會讓整個建模器停住）。
- 功能地圖：「工具」區自己的按鈕（拉出來、放回、收起）歸「工具」大組。
- 面板收合鈕的滑鼠說明改成「工具那一區會變成浮動視窗，面板打開時回來」（本機驗時看到還寫著 1a 的「搬回工具列」）。
