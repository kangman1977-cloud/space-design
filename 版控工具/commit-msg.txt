【🔴 這一輪真正的收穫：日誌不是漏寫，是流程沒有那一步】

kang：「明明有實測...為什麼都沒記錄到」

查 git log，那一輪 8 個 commit 裡提到他的只有兩個：
  59c23d3 凹的面上新拉的線會跑出邊界 —— kang 實測抓到
  4f23c4e 顯示點 —— kang 實測抓到「新加的點看不到位置」
兩個都是「抓到 bug」。他說 OK 的那些，一個都沒有。

  他說「這裡怪怪的」→ 要修 → 有改檔 → 有差異
                    → 我要寫 commit-msg → 順手就回寫日誌了
  他說「OK」        → 沒有東西要改 → 沒有改檔、沒有差異、沒有 commit
                    → 整條回寫鏈一次都沒被觸發

🔴 所以「通過」是這套流程裡唯一不產生任何動作的事件 ——
   而它偏偏是最該記的，因為通過等於一個功能可以結案。

⚠ 而且工作流程那五步（改檔 → 看差異 → 寫 commit-msg → 存檔 → 上傳）
   結束在「上傳」，實測卻發生在上傳之後（要有網址他才測得到）。
   流程根本沒有第 6 步。

→ 下一輪就補這一步，並訂「功能沒有實測結果就不算完成」。
