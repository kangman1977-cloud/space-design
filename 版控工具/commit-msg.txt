入口頁加上建模器，並讓建模器也能「加到主畫面」

第 3 期做完之後建模器可以投入生產了，但入口頁還沒有它的連結，
在平板上得手動打網址。這一筆把它補上。

新增 4 個檔，修改 2 個檔（+19 / -2）。程式邏輯一行都沒動。

【新增】

  icons/modeler-512.png / 192 / 180
      白底圓角 + 等角折板 + 紅色折線。折板正是建模器現在的主力
      （第 3 期做完就是為了折彎件），紅色折線沿用專案既有的紅色語彙。
      白底圓角跟「說明表」同一組，深色與淺色背景都看得清楚，
      縮到 64px 仍然讀得出來。圖形置中收在中央 80% 內，符合 maskable 安全區。

  manifest-modeler.webmanifest
      跟另外兩份並排放在根目錄。
      **scope 用 ./建模器/ 而不是另外兩個的 ./** ——
      從主畫面開建模器時視窗只圈住建模器，
      不小心點回首頁會用一般瀏覽器開，不會把 PWA 視窗帶走。

【修改】

  index.html（入口頁）
      第三張卡片「建模器 -> 建模器/」。
      .apps 是 1fr 1fr，第三張自然落到第二列，**CSS 一行都沒改**。
      頁尾補一句：建模器要從這一頁點進去（它由多個檔案組成，
      直接雙擊檔案開不起來）。

  建模器/index.html
      head 加 5 行：manifest、theme-color、apple 三件套。純加法。
      manifest 與圖示走 ../ 指回根目錄；manifest 內的路徑是相對於
      manifest 自己的位置，所以照樣寫 icons/... 即可。

      **black-translucent 是刻意加的**（跟另外兩個工具一致）。
      它會讓內容延伸到 iOS 狀態列底下 —— 那正是踩過的坑第 7 條，
      但建模器的版面本來就全靠 env(safe-area-inset-*) 讓開，所以安全。
      這件事桌機看不出來，已請 kang 在 iPad 上實測。

【驗證】

  - 兩個 HTML 引用的 10 個路徑全部存在（程式逐一檢查）
  - 三份 manifest 都是合法 JSON，start_url 與 scope 都對
  - 兩個 HTML 的大括號與 @media 配對正確，外部網路依賴 0
  - node 建模器/tests/run.mjs -> 407 項全過（本來就沒動到邏輯）
  - kang 實測：電腦與 iPad 都能從入口頁進入建模器

  順帶記一件跟程式無關、但會再遇到的事：
  kang 的電腦上 localhost:8080 曾被另一個專案的 Service Worker 佔住，
  導致開出來是舊專案的畫面（iPad 沒事，因為那是不同的網址來源）。
  清法：網址列 ⓘ -> 網站設定 -> 刪除資料 -> Ctrl+Shift+R。
  本專案刻意沒有 Service Worker，所以不會反過來影響別人。
