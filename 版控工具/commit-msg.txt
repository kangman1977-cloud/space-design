建模器第 2 期（下）：管、圓角方塊、折板，以及板件顯示厚度

第 2 期到此完成。新增三個參數體，其中折板是第 3 期鈑金展開的主角。

【折板做成「折彎序列」，不是寫死 L 型／U 型】

  一道折彎 = 轉幾度 + 內圓角多大 + 轉完再走多長
    一道        -> L 型
    兩道同向    -> U 型
    兩道一正一負 -> Z 型
    想折幾道就加幾道

實際鈑金件常常折三、四道。寫死只能做兩種，序列是同一套邏輯涵蓋
全部，而且第 3 期展開讀的就是這個序列，不必再從網格反推。

面板可以「+ 加一道折彎」「移除這一道」，並即時顯示展開總長。

這也是**半邊結構的「邊角色」欄位第一次真正派上用場** ——
折彎圓弧被切成 arcSeg 段，段與段不共面，autoMarkFolds() 自動把
它們標成折線（fold）。第 1 期留了這個欄位但一直沒有東西產生折線。

【板件在畫面上看得到厚度了】

資料層仍然是「一張沒有厚度的中性面 + 厚度屬性」（日誌第 3 個
關鍵決定，展開要靠它），只有**顯示時**才用 mesh.shell() 撐開。
加厚的結果只活在 GPU 上，文件一個位元組都沒動 ——
符合「畫面是文件的投影，自己不存狀態」。

在此之前平板看起來就是一張紙，沒辦法確認板厚設對沒有。

【兩個靠數學才抓得到的問題】

1. 展開長度不能用網格量（會少算，而且是往少的方向錯）

   圓弧在網格上被切成直線段，**弦長比弧長短**。同一片折板：
     網格量到的   73.12 cm
     真正的展開長 73.14 cm
   差 0.03%，折三道就差到零點幾公分。雷切下去才發現就來不及。

   所以另外寫了 bendDevelopedLength() 用 r x theta 算，
   面板顯示的、第 3 期出圖要用的都是這個數字。
   註解已寫明：等第 3 期做 K 因子時，中性面位置會改由板厚與
   K 值決定，屆時只要改這一個函式。

2. 加厚時折彎處會被削薄（測試抓出來的，肉眼看不到）

   第一版沿頂點法向推 t/2，體積少了 0.076%。
   頂點法向是角平分線，只推 t/2 的話折角處實際厚度變成
   t x cos(半夾角)，90 度折就只剩 0.71 倍。
   正確做法是除以那個餘弦（鈑金與繪圖裡的「尖角接合 miter」）。

   修正後 1 / 3 / 8 段、45 / 90 / 135 度各種組合都精確到
   浮點誤差（1e-12）。

【修正：板件不能做陣列】

kang 實測時發現板件陣列整個失敗，被布林擋下。

修法不是「想辦法讓布林吃下去」，而是認清**語意本來就不同**：

  實體 -> 布林聯集。兩份重疊處只能算一次，接縫要真的縫起來。
  板件 -> 直接拼接，不合併。12 片一樣的側板就是 12 片，
          展開時要分開出圖；黏成一體反而讓第 3 期分不出來。
          板件是開放的面，本來也沒有內外之分可以做布林。

新增 Mesh.merge()：把多個網格併進同一份資料，但不做任何合併運算，
各自仍是獨立的殼，位置相同的頂點也不焊接。折線標記會一起搬過去 ——
**掉了折線第 3 期就展不開**，所以測試特別盯這一項
（5 條折線的折板做成 5 片，必須是 25 條）。

判斷依據用「網格封不封閉」而不是物件的 kind ——
kind 是使用者隨手可改的標籤，封閉與否才是幾何事實。

順帶放寬：陣列按鈕不再要求布林函式庫已載入（板件陣列用不到它）。
但布林本身仍然擋下板件，那個限制是對的，測試也補了一項守著。
