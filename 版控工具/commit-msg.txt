【這一輪在補一個會讓料切錯的洞】

  圓錐的展開長度目前是**弦長相加**，而弦長永遠比弧長短。實測：

    seg=32（預設）  短少 0.16%（3 mm）
    seg=16          短少 0.64%（1.2 cm）
    seg=8           短少 2.55%（4.8 cm）

  分段數越少錯越多 —— 而鈑金正好會把 seg 調小（seg 就是實際要滾的稜線數）。
  4.8 cm 不是誤差，是接不起來。

  原因：第 3 期的圓弧修正是「沿垂直於折線方向的一維拉伸」，
  這個做法**只在折線互相平行時成立**。圓柱的折線平行，所以圓柱是精確的
  （實測誤差 0.0000%）；圓錐的折線指向頂點，分組就散掉了，修正整個不觸發。

  真正的修法是極座標展開，那是第 5 期(B)。這一輪只做止血：
  **算不準的片一定要講出來**，不要一聲不吭給一個偏短的數字。

【新增 foldsNonParallel（flatten.js）】

  一片裡的折線若不是全部互相平行，就標記起來，並推一則
  開頭是「請勿據以下料」的警告。

  它問的是一個明確而且答得出來的問題：
  「一維拉伸修正的前提成不成立？」——而不是去猜結果對不對。

  實測涵蓋率：
    抓到  圓錐（8/16/32 段）、球冠
    不誤報 平板、折板 L/U/Z、圓柱側面（8 段與 64 段）、壓克力封閉方塊六片

  球冠那條特別值得留著：它的 overlap 是 false，**重疊偵測救不了它**，
  因為攤平時演算法自己補的隱含切割線把裂縫撐開了。

【nonDevelopable 維持 false，但補上一大段「為什麼做不出來」】

  照原計畫用角虧（離散高斯曲率）實作過，**它會給錯答案**，
  而且錯在「哪些頂點算內部」這個定義上，兩種定義各錯一半：

    定義                      圓柱側面  圓錐    球冠
    整個網格的內部點           可展 OK   不可展 X 不可展 OK
    扣掉所有切割線碰到的點     可展 OK   可展 OK  可展 X

  圓錐的頂點角虧確實不為零，但接縫一剪開就攤得平 —— 圓錐是可展的。
  球冠反過來，隱含切割線讓每個點看起來都攤得平，但那張圖裂了一堆縫。

  差別在於**切割線是誰決定的**：圓錐的接縫非剪不可，
  球冠的裂縫是演算法沒辦法才補的。要分辨這兩者，等於要先決定
  「這一片該切在哪」—— 那正是第 7 期的自動分片。

  -> 寧可留一個誠實的 false，也不要放一個會在圓錐上說「可以下料」的判定。
     這是踩過的坑第 5 條：寫「應該是多少」的判定之前，
     先問清楚這條規則的成立條件。這裡問了，答案是「現在還答不出來」。

【一度加了「封閉實體一律拒絕展開」，被測試打回來】

  加上去之後回歸測試 3 項失敗，全在「封閉實體 拆成 3 種面」那組。
  那不是舊 bug，是**合法用途**：封閉實體遇到不能折的材料（壓克力、木板），
  每條稜線都變成切割線，方塊因此拆成六片各自平坦的面 ——
  壓克力箱體就是這樣六片分開下料再黏起來的。

  封不封閉根本不是判準，拿它當判準就會誤傷這條路。
  真正會出事的「封閉實體 + 折得動的材料」已經被 foldsNonParallel 抓住了。

  -> 已退掉，並把這段寫成註解 + 一條迴歸測試盯著，免得日後有人再加一次。
  -> 這次是測試擋下來的，不是我看出來的。
