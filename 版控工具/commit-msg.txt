【這一期的核心：弧長不等於弦長】

日誌「踩過的坑」第 6 條說展開長度不能用網格量，這一期真正把它做掉。

  圓弧在網格上被切成 arcSeg 段直線，弦長永遠比弧長短：
      弦長 = m x 2r x sin(theta/2m)      弧長 = r x theta

  flatten.js 會辨識出「哪幾條折線其實同屬一段圓弧」（等寬 + 等角
  的連續段），再把那一段拉長到真正的弧長。

  **驗證方式是交叉對答案**：flatten.js 是從網格辨識算出來的，
  bendDevelopedLength() 是從參數直接套公式，兩條完全獨立的路，
  arcSeg 2/3/4/6/8/12/24 全部一致到 1e-14。這跟第 2 期
  「參數體管 vs 布林大減小」是同一招。

  同時驗「修正真的有在動」：修正後的長度必須明顯大於弦長總和，
  不然有沒有做修正根本測不出來。

【折彎半徑改成內側 R ＋ K 因子】

原本 bends[].r 當成中性面半徑用。改成 bends[].ri = 內側圓角，
另加 k = K 因子，中性層半徑由公式推出：

      rn = ri + K x t

  為什麼要改：中性層是算出來的，現場量不到。師傅講「折 R3」、
  圖面標的、模具標的，全部都是內側圓角。存內側 R 才對得上現實。
  而且 K 是材料屬性，正好落在既有的「材料規則獨立、幾何共用」分層裡。

  差多少（3mm 鐵板、內 R3、折 90 度、四道）：
      照內側 R 算  4.71mm x 4 = 18.8mm
      照中性層算   6.60mm x 4 = 26.4mm
  差 7.6mm。板子短這麼多，折完裝不上去。

  檔案格式 v3 -> v4。轉換走 ri = r - K x t，生成時再算回
  rn = ri + K x t = r，所以**舊檔開起來形狀一模一樣**，
  展開長度也一樣。測試有一項專門盯這件事，並會鑽進布林樹與陣列裡。

  板厚會影響幾何，所以 buildSrc() 多帶一個板厚參數。用閉包往下傳，
  bool.js 與 array.js 完全不必知道有這回事，兩個檔一個字都沒改。

【踩到的四個坑（已寫進程式碼註解，日誌待補）】

  第 9 條  規格上合法 != 別人的軟體讀得動

    第一版 DXF 只寫了 HEADER / TABLES(只有 LAYER) / ENTITIES 三段。
    完全符合 R12 規格，AutoCAD 讀得動，**Illustrator 直接跳錯誤視窗**。
    缺的是 BLOCKS 區段（空的也要有）、LTYPE 表、STYLE 表、圖層 0。
    另外 $INSUNITS 是 R14 才有的變數，寫在 AC1009 裡是時代錯亂，已移除。

    SVG 則是沒寫 XML 宣告，Illustrator 根本沒認出那是 SVG，
    當成純文字檔開，畫面一堆標籤原始碼，中文還變亂碼。
    另外 dominant-baseline 它不支援，所有標註會往上跳半個字高。
    線寬也錯了：寫成 0.35 個使用者單位，而 1 單位 = 1cm，
    印出來是 3.5mm 粗，製圖標準大概 0.5mm，粗了七倍。

    -> 規則：要送出去給別人開的格式，只能用最保守的寫法，
       而且**一定要用真正的目標軟體開過才算驗證**。
       沙箱測試與「瀏覽器看起來對」都不算。

  第 10 條  圓弧至少要切兩段才認得出來

    切一段的「圓弧」在網格上就是一個平面四邊形，跟一個倒角
    **完全一樣**，沒有任何幾何資訊能分辨。這不是演算法保守，
    是資訊真的不存在。所以 prim.js 的 arcSeg 下限設成 2。

  第 11 條  「產生 <a download> 然後 click」有三個地雷

    實測存出來的檔案叫「尚未確認的 636844.DXF」—— 那是 Chrome
    自己的暫存名，副檔名還被改成大寫，Illustrator 因此認不得。
    看起來像匯出壞掉，其實檔案內容完全正確。另外還留下一堆
    .crdownload 沒下載完。三個原因：

      1. <a> 沒掛進 DOM，Chrome 忽略 download 檔名
      2. blob URL 1 秒就 revoke，下載被中斷（改成 5 秒）
      3. 連續下載多個檔案只放行第一個（改成錯開 250ms）

    -> 修法直接沿用組裝系統結構說明表已經驗證過的那一套，
       抽成 js/out/save.js 共用，兩個工具的存檔行為因此一致。
    -> 順帶補上「指定存放位置」（File System Access API）。
       注意它只在**安全環境**可用：https 或 localhost。
       本機用內網 IP 開屬於非安全環境，會自動退回一般下載，
       所以勾選框會淡化並在提示裡講清楚原因 —— 沉默地退回
       是最糟的做法，使用者會以為勾選壞掉了。

  第 12 條  讀不出尺寸的圖，比沒有圖更糟

    折彎多的件（圓角方塊 21 道）分段尺寸全擠在同一排，
    變成一團「0.9787.05.24」。看的人會以為自己讀到了。

    -> 但也不能因為放不下就不標：折彎區只有 3.33cm，
       那個數字正是師傅畫線要用的，丟掉等於這張圖不能下料。
       改成錯開兩排，兩排都塞不下才放棄（並到備料明細去查）。
    -> 測試加了一組自動偵測標註重疊的檢查，四種件都是 0 處。

【驗證（能用數學對答案的都對過了）】

  展開長度   網格辨識 = 參數公式，arcSeg 2~24 全部差 1e-14
  四種形狀   L / U / Z / 四道混合，展開長、板寬、折彎道數全對
  辨識回推   內側R、中性層R、角度、每一道的展開弧長都對得回輸入值
  圓筒側面   8/16/32/64/128 段，展開長 = 2 x pi x r，誤差 1 微米內
             （繞一圈的網格會自動剪開一條縫，兩端那兩片仍算在圓弧裡）
  平板       100 x 60 精確。曾經拿三角化的對角線當基準而歪成 116.6 x 102.9
  K 因子     板厚 0.1 -> 1.0，展開長增加量精確等於 (pi/2) x 0.4 x 0.9
  舊檔相容   v3 檔轉 v4 後，網格面積與展開長完全不變
  分段尺寸   展開圖上各段相加 = 總長（師傅照這些數字畫線）
  標註重疊   四種件自動偵測，全部 0 處
  檔名       Windows 不合法字元、空字串、長度上限、中文保留
  DXF        四個區段順序、三張表順序（LTYPE 必須在 LAYER 前）、
             TABLE/ENDTAB 與 SECTION/ENDSEC 成對、全 CRLF、全 ASCII、
             每個 TEXT 都指定 STANDARD 樣式、mm 換算倍率
  SVG        XML 宣告、UTF-8、不用 dominant-baseline、線寬 <= 0.6mm
  效能       128 段圓柱展開 2ms

  畫面與匯出檔案由 kang 實際開啟確認（沙箱下載不到瀏覽器，
  也裝不了 Illustrator）。

【已知限制（如實記錄，不是 bug）】

  - 圓錐與圓角方塊的展開仍走弦長：折線不平行，一維拉伸不適用。
    那是第 5 期（展開 v2：圓柱、圓錐、錐形接頭）的範圍。
  - 重疊只偵測不分片。自動分片是第 7 期，佔整個展開引擎約 70% 工作量，
    而且一定要搭配手動調整切線，不能強迫接受電腦的判斷。
  - 等寬等角的連續折面會被判定成圓弧 —— 因為它幾何上就是。
    刻意要做成折面板的話，要等第 6 期的面編輯才表達得出來。
  - 封閉實體展不開，會明確告知要先抽殼或標出切割線。
