建模器第 2 期（上）：布林運算，存運算樹而不是存三角形

差集／聯集／交集三種布林運算。產生的物件存的是「方塊 減去 圓柱」
這件事本身，不是挖完的三角形，所以事後還能回頭改孔徑與孔的位置。
這是延續第 1 期第 2 個關鍵決定（存參數不存三角形）。

【推翻原訂計畫：改用 Manifold，不是 three-bvh-csg】

日誌原本寫第 2 期要「換成 BVH 加速版」。實測後發現不行。

同一題（方塊 60x45x40 挖 ⌀20 貫孔）：

                        three-bvh-csg      Manifold
  耗時                      40 ms            0 ms
  三角形                     376             144
  尤拉數（應為 0）           -113  X            0  OK
  網格封閉                    否              是
  結構問題                  244 項            0 項
  角虧總和（應為 0）           --         0.000000  OK

兩邊算出來的體積都對，畫面看起來也一樣，差別在結構裡面：
three-bvh-csg 把原三角形切開再拼回去，切完之後鄰居關係斷了 506 處。

平常看不出來，但第 3 期展開引擎做的第一件事就是「問這條邊隔壁
是哪個面」，斷掉的地方答不出來，展開會直接失效。而且這是它的
設計取捨，不是等人修就會好的 bug。

Manifold（elalish/manifold，Apache-2.0）的設計目標就是保證輸出
封閉可接，使用者含 OpenSCAD、Blender、Godot、BRL-CAD、Babylon.js。
已本地化到 建模器/lib/manifold/，不靠網路，做法與 three.js 一致。

【風險控管：換庫只要改一個檔】

Manifold 只被 js/build/bool.js 這一個檔案 import，其他程式碼一律
透過我們自己的介面呼叫。將來要換掉它，運算樹格式、面板、Undo、
存讀檔都不用動。沿用日誌既有的「規則分開、幾何共用」分層原則。

【設計決定】

1. 檔案格式 v2，v1 舊檔照樣讀得動
   src 新增 type:'bool'，內含 op 與 items，每個 item 帶自己的
   位置角度縮放，item.src 本身也可以是 bool，所以能巢狀。
   v1 -> v2 不需要補欄位（v1 年代不可能有布林物件）。

2. 運算元的座標是相對於第一個物件（母體）的
   結果物件沿用母體的位置與角度，看起來就像「在 A 身上挖了洞」。
   移動整個結果時孔會跟著走；在面板改運算元位置則是改相對位置。

3. 啟動時一次等 WASM 載完，之後全程同步
   Manifold 是 WebAssembly，一定非同步。但建模器的資料流
   （操作 -> 改 Doc -> view.sync）是同步的，若讓 mesh() 變成非同步，
   等於要改寫每一處呼叫。改成在 boot() 開頭等一次，風險小得多。
   載入失敗不讓程式掛掉，只是布林按鈕不能按，並提示要用伺服器開。

4. 生成網格失敗一律接住，不往外丟
   mesh() 是在畫面更新途中被呼叫的，例外丟出去會變白畫面。
   改成記在 obj.error，面板顯示紅色提示，並退回「第一個運算元」
   當替身，看得出是哪個物件出問題。

5. 提供「凍結成網格」
   確定不再改的模型可以凍結，開檔就不必重算布林。
   資訊只能往下走，所以預設留在資訊多的那一端（運算樹）。
