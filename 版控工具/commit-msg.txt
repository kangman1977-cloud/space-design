新增入口頁與上傳工具，準備部署到 GitHub Pages

【index.html】兩個工具的入口頁
上線後檔名是中文，網址會被編碼成一長串百分號，平板上根本打不出來。
有入口頁就只要記一個短網址，進去用點的。
- 兩張卡片連到各自的工具，附圖示與說明
- 說明平板要按「加入主畫面」、以及資料存在本機不會上傳
- 提到兩個工具可用 JSON 互通
- 已確認所有連結的檔案都存在、CSS 結構正確

【.nojekyll】停用 GitHub Pages 的 Jekyll 處理
避免中文檔名或特殊路徑被它吃掉。空檔案，沒有其他作用。

【版控工具/3-上傳網路.bat】一鍵推送
- 純加法：只上傳，不刪本機檔案、不改寫歷史
- 沿用既有設計：產生結果檔給 AI 讀、純 ASCII + CRLF、stale lock 偵測
- 推送前先列出「有沒有沒存檔的東西」「會送出哪幾個 commit」
- 還沒設定遠端時，直接印出該做什麼，不會靜默失敗

【部署前置檢查】
已確認兩個網頁與 manifest 內全部是相對路徑，沒有任何以 / 開頭的絕對路徑，
因此放在 GitHub Pages 的子目錄（/repo-name/）底下也能正常運作。

【過程中修正的自身錯誤】
第一版 3-上傳網路.bat 的註解裡混入中文，違反 .bat 純 ASCII 規則；
更糟的是我的轉檔腳本寫成 open(檔案,'wb').write(內容.encode(...))，
以 wb 開檔會先清空檔案，encode 才拋例外，結果檔案變成 0 bytes。
已改為「先編碼驗證成功，才開檔寫入」，並對四支 .bat 全部重新驗證。
這也是 1-看差異.bat 第 [5] 段「各檔絕對行數」存在的理由。
