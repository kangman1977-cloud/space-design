# 版控工具（網頁空間設計程式）

最後更新：2026-08-20

> 設計參考自 `D:\彩藝通ERP系統\版控工具`，但**依本專案屬性調整過，不是照抄**。
> 差異與理由見下方「為什麼跟 ERP 不一樣」。

---

## 日常怎麼用

| 順序 | 動作 | 誰做 |
|---|---|---|
| 1 | AI 說「改好了」 | AI |
| 2 | 雙擊 **`1-看差異.bat`**（唯讀，零風險） | kang |
| 3 | 告訴 AI「看差異跑好了」，AI 自己讀結果檔 | AI |
| 4 | AI 確認沒動到不該動的地方、並寫好 `commit-msg.txt` | AI |
| 5 | 雙擊 **`2-存檔.bat`** | kang |

**先看再存。** 步驟 2 是唯讀的，誤按最多覆蓋一個文字檔，專案一個位元組都不會變。

---

## 各支做什麼

| 檔名 | 做什麼 | 性質 |
|---|---|---|
| `1-看差異.bat` | status／分支／stat／逐行 diff／各檔行數／最近 5 次 | **唯讀** |
| `2-存檔.bat` | status／add／stat／commit -F／最近 10 次 | **純加法** |
| `3-上傳網路.bat` | push 到 GitHub，更新公開網頁 | **純加法** |
| `平板測試-啟動伺服器.bat` | 把資料夾分享到內網給平板測試 | **唯讀** |

全部都不會刪東西。

`3-上傳網路.bat` 在還沒設定遠端時會直接告訴你要做什麼，不會靜默失敗。
推送後 GitHub Pages 約 1～2 分鐘才會更新，平板可能還會看到舊頁面一下子。

### ⛔ 為什麼沒有「切分支」和「退回」的一鍵

沿用 ERP 的判準：**一鍵只給「唯讀」與「純加法」；會改變現況的動作不給捷徑。**

- **退回**是唯一會讓檔案消失的動作
- **切分支**雖然不刪檔案，但會換掉工作目錄的內容，而且「切到哪」跟「退到哪」一樣有很多種——一支 `.bat` 做死一種，做寬了危險、做窄了沒用

→ 要切分支或退回時，**由 AI 當場給出那一行指令**，kang 貼進 Git Bash。多花十秒，換到「知道自己正在做什麼」。

## 為什麼跟 ERP 不一樣

| 項目 | ERP | 這裡 | 理由 |
|---|---|---|---|
| `1-建立版控` / `2-第一次存檔` | 有 | **沒有** | 已經 init 並完成第一個 commit |
| 「停下來驗證排除清單」儀式 | 必要 | **省略** | 這裡只有 3 個檔、沒有 `.env`、沒有 `node_modules`，`.gitignore` 出錯風險趨近於零 |
| `git count-objects`（倉庫大小） | 有 | **拿掉** | 檔案永遠只有幾百 KB，盯它只是讓輸出變長 |
| 分支顯示 | 沒有 | **加上** | 這裡有 `main` / `touch` 並行，改到一半要知道自己在哪 |
| 各檔絕對行數 | 沒有 | **加上** | `git diff --stat` 只顯示增減；單檔巨石被寫壞時，「這個檔現在總共剩幾行」才是關鍵指標 |
| 編號順序 | 建立→存檔→看差異 | **看差異→存檔** | 編號順序＝操作順序，先看再存 |

### 本專案的特徵性風險

每個網頁都是**單一 1000+ 行的檔案**，HTML、CSS、JS 混在一起，而 AI 一次改動動輒 200 行。

2026-08-20 的實例：插入 CSS 時誤刪了 `@media print {` 這個開頭，導致底下十條列印規則變成全域生效，側欄和工具列全部消失。當時大括號仍然平衡、JS 語法完全正確、瀏覽器沒有任何錯誤訊息。

**這類錯誤語法檢查抓不到，只有 diff 抓得到。** 這就是為什麼在這個專案裡，「看差異」比在 ERP 更重要。

## 驗證分工

兩邊各驗自己擅長的，互補而非重疊：

| 誰 | 驗什麼 | 工具 |
|---|---|---|
| **AI（沙箱）** | JS 語法、CSS 大括號配對、`@media` 是否正確閉合、函式與 DOM 元素是否存在、排料數學 | node / python |
| **`.bat`（kang 雙擊）** | git 狀態、逐行 diff、分支位置、檔案行數 | 產生結果檔給 AI 讀 |

沙箱驗「程式對不對」，diff 驗「有沒有動到不該動的地方」。**2026-08-20 那個錯誤前者抓不到、後者抓得到。**

## 給 AI 的

- **存檔說明**寫進 `commit-msg.txt`（UTF-8），`.bat` 用 `-F` 讀它。**每次叫 kang 存檔前重寫這支。**
  檔名刻意用 ASCII——它的路徑被寫在 `.bat` 內容裡。
- **結果檔** `git-log-*.txt` 由 `.bat` 產生，用 Read 直接看，**不要叫 kang 貼畫面**。
- 結果檔已在根目錄 `.gitignore` 內，不會進版控。
- 🔴 **`.bat` 內容一律純 ASCII**（含註解與 echo）。Big5 環境含中文會亂碼——**檔名可以中文，內容不行。**
- 🔴🔴 **沙箱一律不執行 `git` 指令——包含唯讀的 `git status` / `git diff` / `git ls-files`。**
  不是「不能做會改變狀態的動作」而已：**連唯讀指令都會建立 `.git\index.lock`，
  而沙箱刪不掉它**，下次 kang 存檔就會 fatal 失敗。
  〔2026-08-20 實例：AI 在沙箱跑 `git status` 等指令做檢查，留下 stale lock，
  `2-存檔.bat` 直接失敗。AI 讀過 ERP 那條規則，卻理解成只禁寫入動作。〕
  → 沙箱只能用 Read／grep／awk **讀檔案內容**，包括讀 `git-log-*.txt`。
  → 兩支 `.bat` 都已加入 stale lock 偵測，會擋下來並印出清除指令。
  → 清除方式（kang 在 Git Bash 執行）：
  ```
  find .git -name "*.lock" -delete
  find .git -name "tmp_obj_*" -delete
  ```
- 改完檔案後，沙箱端一定要跑結構檢查（大括號、`@media` 閉合、破壞性規則是否包在該有的 media query 內）。

## 這東西是可逆的

刪掉根目錄的 `.git` 資料夾 → 回到什麼都沒發生的狀態，專案檔案一個位元組都沒被改過。
